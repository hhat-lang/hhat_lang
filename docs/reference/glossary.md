
# Glossary

In this page you can find the table of contents for [acronyms](#acronyms), its meanings and descriptions, and [terminologies](#terminologies) and their meanings/descriptions. The entries are in _alphabetical order_. More entries are being added from time to time.


## Acronyms

| Acronym | Meaning | Description |
|----|----|----|
| CLI | command line interface | A user interface through typing commands on the terminal. |
| HIR | high-level IR | A high-level IR that usually contains more information about the original source code. Useful for debugging early stages of the copmilation pass, for instance to catch up parsing errors. |
| IR | intermediate representation | A code user internally by the compiler that represents the source code. |
| MIR | mid-level IR | A mid-level IR that is usually stripped off of the original source code. It is closer to the machine code and contains more instructions from the internal compiler logic, internal checks, diagnostics. |
| Q3L | quantum low-level language | A quantum language with quantum physics constructs, such as qubits, gates or Hamiltonians/pulses, quantum circuit, etc., that can be used by quantum backends for executing quantum programs. Examples are OpenQASM v2, [OpenQASM v3](https://openqasm.com/), [NetQASM](https://arxiv.org/abs/2111.09823), [cQASM](https://qutech-delft.github.io/cQASM-spec/latest/). |
| QPU | quantum processing unit | A quantum mechanics-based hardware that uses qubits as the processing units. |


## Terminologies

| Terminology | Meaning/Description |
|----|----|
| Compiler pass | A stage of compilation in which some specific processing, transformation, optimization, or lowering happens. |
| Quantum backend | A target device or simulator that can be used to execute quantum programs. |
