## Communication Guidelines

### Choosing the Right Platform

**Use Discord for**:

* Quick questions
* Real-time collaboration
* Casual chat
* Urgent help

**Use GitHub Discussions for**:

* Feature proposals
* Design discussions
* Searchable Q&A
* Formal announcements

**Use GitHub Issues for**:

* Bug reports
* Feature requests (with implementation plan)
* Tracking work

### Discussion Etiquette

#### Do's ✅

* **Search first**: Check if your topic exists
* **Be specific**: Clear titles and descriptions
* **Stay on topic**: Keep discussions focused
* **Be respectful**: Disagree constructively
* **Give credit**: Attribute ideas and code
* **Follow up**: Update discussions with outcomes

#### Don'ts ❌

* **Don't spam**: One thread per topic
* **Don't hijack**: Start a new discussion if it's different
* **Don't demand**: Be polite when asking
* **Don't cross-post**: Choose one platform
* **Don't ping maintainers** unnecessarily

### Writing Good Discussion Posts

#### Title

```markdown
❌ "Need help"
✅ "How to implement custom quantum gates in Heather?"

❌ "Bug"
✅ "Type inference fails with nested generic functions"

❌ "Idea"
✅ "Proposal: Add pattern matching for quantum measurement results"
```

#### Description

**Include**:

1. **Context**: What you're trying to do
2. **Problem/Question**: What specific help you need
3. **What you've tried**: Your attempts so far
4. **Code samples**: Minimal reproducible examples
5. **Expected outcome**: What you want to achieve

**Example**:

```markdown
## Context
I'm implementing a quantum algorithm that requires custom gates.

## Question
How can I define a custom two-qubit gate in Heather?

## What I've Tried
I tried using:
```heather
fn my_gate(q1:qubit, q2:qubit) -> tuple<qubit, qubit> {
    // ???
}
```

But I'm not sure how to specify the gate matrix.

## Expected Outcome
I want to create a gate with this unitary matrix:
[matrix here]
```

## Community Initiatives

### Working Groups

Specialized groups focusing on specific areas:

* **Syntax & Language Design**: Refining Heather and exploring new dialects
* **Compiler Development**: Core implementation work
* **Documentation**: Writing guides and examples
* **Quantum Libraries**: Building reusable quantum algorithms
* **Education**: Creating learning materials

**Join a working group**:

1. Express interest on Discord or Discussions
2. Introduce yourself and your background
3. Check the group's current focus
4. Start contributing!

### Regular Events

#### Weekly Office Hours

* **When**: Announced on Discord
* **Where**: Discord voice channel
* **What**: Open Q&A, help, discussion

#### Monthly Community Call

* **When**: First Tuesday of each month
* **Where**: Video call (link in Discord)
* **What**: Updates, demos, planning

#### Quarterly Hackathons

* **When**: Quarterly
* **Where**: Online
* **What**: Focused coding sprints on specific features

## Archives & Resources

### Meeting Notes

Important decisions and discussions are documented:

* **Location**: GitHub Discussions with `meeting-notes` label
* **Contents**: Summaries, decisions, action items

### RFCs (Request for Comments)

Major changes go through RFC process:

* **Location**: GitHub Discussions with `RFC` label
* **Process**: Proposal → Discussion → Decision → Implementation

### Voting & Consensus

For contentious decisions:

* Community input is gathered
* Maintainers make final calls
* Rationale is documented
* Alternatives are considered
